# Процесс: обновление сайта

Обновите сайт из локального профиля бизнеса.

## Входные данные

- профиль бизнеса
- услуги
- контакты
- тон общения

## Файлы сайта

Корневой `website/` содержит код и учебный шаблон в Git. Рабочие контакты и цены формируются только в `.frontsmith/business/website/`. Команда обновления не переписывает исходный шаблон. Для фирменной адаптации одной компании используйте навык `.agents/skills/frontsmith-brand/SKILL.md`: источники оформления находятся в приватном `design/`, а результат — в `website/` рабочей области бизнеса. Общий шаблон меняют только для улучшения самого стартер-кита.

При наличии `design/brand.json` генерация использует фирменные токены, светлую/тёмную темы и `design/site/index.html` (если создан) с `design/site/site.css`. Повторное обновление сохраняет эти источники и обновляемые привязки профиля. Ручные изменения HTML, управляемых CSS и JS в результате не перезаписываются: сначала сравните их и перенесите согласованное в источники. `--force` — отдельная явная замена с резервной копией вне репозитория.

```text
.frontsmith/business/website/index.html
.frontsmith/business/website/styles.css
.frontsmith/business/website/script.js
.frontsmith/business/website/frontsmith-mark.svg
```

## Проверка оператором

После обновления Frontsmith сохраняет материалы проверки запуска и запись действия:

```text
.frontsmith/business/launch/website-review.md
.frontsmith/business/activity/latest-website-update.md
```

Отчёт проверки должен содержать:

- краткую сводку;
- изменённые файлы;
- обновлённые поля профиля;
- связь профиля и сайта;
- инструкции локального предпросмотра;
- препятствия публикации;
- материалы;
- границы безопасности.

Предложите владельцу проверить:

- название бизнеса и контакты;
- названия и описания услуг;
- призывы к действию;
- утверждения, которые нужно смягчить или удалить.

## Безопасность

Обновление локальное. Публикация, изменение DNS, настройка сервисов и реальная доставка заявок требуют явного согласия владельца.
