# CLI регистрации

Команды выполняются из корня репозитория. `node scripts/office.mjs help` — актуальный список. Чтение: `list customers|inquiries|orders`, `match`, `show customer|vehicle|inquiry|order --id ID`. `show order` включает позиции, связанные обращения и события журнала. Часовой пояс: `business.time_zone` (профиль `business.json`), по умолчанию Europe/Moscow.

`report:register` принимает **один JSON-объект через UTF-8 stdin**, без временного файла. Пример PowerShell; значения сформируй из разобранных и уточнённых фактов, без вставки недоверенного текста в исполняемый код:

```powershell
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)
$report = @{
  vehicleId = '<ID из match/show>'
  identityConfirmed = $true
  performedOn = '2026-10-11'
  works = @('Замена рейки', 'Замена колодок')
  finalTotalKopecks = 1700000
  actualDurationMinutes = 480
  basis = 'Отчёт мастера за 11 октября 2026, уточнён владельцем в текущем чате'
  costApprovalBasis = '<фактическое подтверждение согласования клиентом>'
}
$report | ConvertTo-Json -Depth 8 | node scripts/office.mjs report:register --dry-run
# После проверки применить тот же объект
$report | ConvertTo-Json -Depth 8 | node scripts/office.mjs report:register
```

В среде с программным запуском процессов передай сериализованный объект как stdin без оболочки. Не вставляй строки отчёта в shell-команду, используй безопасную передачу данных.

| Поле | Контракт |
| --- | --- |
| `vehicleId`, `identityConfirmed` | существующий проверенный автомобиль, строго `true` |
| `performedOn` | реальный день YYYY-MM-DD, не будущий в часовом поясе бизнеса |
| `works` | непустой массив названий, без цен из каталога |
| `finalTotalKopecks` | целые копейки, ≥ 0; рубли умножить на 100 без округления неизвестных сумм |
| `actualDurationMinutes` | целые 1–525600 или null, без подмены нормативами |
| `durationNote`, `note` | необязательные пояснения длительности и дополнительные сведения |
| `basis` | реальный источник фактов, не вымышленное подтверждение |
| `orderId`, `revision` | существующий заказ и точная числовая revision из show; без них создаётся новый |
| `inquiryId` | необязательно, открытое обращение для нового заказа того же клиента/автомобиля |
| `newOrderConfirmed` | true только после подтверждения отдельного ремонта при наличии активных заказов |
| `costApprovalBasis` | требуется для нового/чернового заказа: действительное основание согласования клиентом |
| `approvedTotalKopecks` | необязательная отдельная согласованная сумма; без неё используется итог отчёта; при наличии позиций должна совпадать с их суммой |

Результат: `status` = `preview`, `registered`, `existing`; `order` — прочитанный из БД заказ. Ошибка даёт ненулевой код CLI. Preview выполняет полную прикладную транзакцию и откатывает её вместе с журналом. Регистрация использует IMMEDIATE-транзакцию, операции `createWorkOrder`, согласования/статусов, `recordWorkResult` и существующий журнал. Дубликат определяется по ID автомобиля, дню, нормализованному отсортированному перечню работ, итогу, минутам и пояснению длительности; уникальный индекс журнала защищает от гонки. Перефразированный или исправленный отчёт требует проверки Codex по истории, поскольку семантическое равенство текстов не вычисляется.

Новый заказ остаётся `ready`. Выдача — отдельная команда `order:status --to completed --completed-at ...` только при известных фактах выдачи. Команда не требует VIN/номера для создания автомобиля, но требует подтверждения его личности. Никакие данные во внешние сервисы не отправляются.

# Сценарии диалоговой проверки

Проверь поведение навыка в отдельном чате с тестовой базой (`FRONTSMITH_BUSINESS_ROOT` на временный каталог), не в рабочем офисе:

- «11 октября 2026, VIN …, замена масла, 2500, час» → поиск, 250000 копеек, 60 минут, дата выполнения; согласование уточнить только если его нет в заказе/контексте.
- «Рейка, колодки, 17000, 8 часов» → две работы, одна общая сумма, 480 минут; не создавать фиктивную разбивку.
- Две машины, 11 и 12 октября → независимые сопоставления/транзакции; не переносить идентификаторы первой на вторую.
- «Мазда 3, ШРУС, шаровая, 6500, 1,5 часа» → 90 минут, вопрос о машине и дате; ответ с номером продолжает тот же ремонт.
- Повтор сохранённого отчёта → прежний номер, нет новых заказов/позиций/событий. Изменённая сумма → уточнить исправление.
- «Ремонт 12000 вместе с деталями» → общая сумма без разделения; неизвестные часы NULL.
- «Заняло 2 дня» → вопрос о фактических часах; при неизвестности пояснение про дни и NULL минут, без 960/2880 минут.

Эти сценарии проверяют решения модели; автоматические SQLite/CLI-тесты находятся в `tests/work-reports.mjs`. Успех автоматических тестов не означает, что диалоговая проверка уже проведена.
