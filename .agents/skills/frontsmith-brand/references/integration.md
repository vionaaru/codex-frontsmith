# Интеграция в Frontsmith

## Источник и результат

Код навыка и общий механизм оформления — в Git. Для компании используется `businessPath("design", ...)`; путь по умолчанию `.frontsmith/business/design/`, с учётом FRONTSMITH_BUSINESS_ROOT. Не использовать абсолютные пути текущего компьютера.

```text
design/
  inputs/                  исходные материалы, не публикуются
  research.md              реестр и выводы
  BRAND-DESIGN.md           фирменная спецификация с источниками
  brand.json               проверяемые токены
  DESIGN.md                самодостаточный Base + Brand для трёх поверхностей
  site/index.html          необязательная клиентская композиция с привязками Frontsmith
  site/site.css            оформление клиентского лендинга
  public/                  только отобранные PNG/JPG/WebP/WOFF2, плоские имена
  review/                  изображения проверки и отчёты
  progress.json            служебные контрольные точки
```

В BRAND-DESIGN.md и DESIGN.md явно раздели landing, office, widget. Исходные три документа BASE/ADAPTATION/WORKFLOW в references — методика лендинга; офисный контракт читается отдельно. Не переписывай общую методику при работе для одной компании.

## Токены

`brand.json`: `version: 1`, `font` (стек системных шрифтов без CSS-инъекций), `radius` (0–32), объекты `light` и `dark`. В каждой теме обязательны роли `page`, `surface`, `surfaceMuted`, `text`, `textMuted`, `border`, `accent`, `onAccent`, `accentSoft`, `focus`, `success`, `warning`, `error`; значения — #RRGGBB. Смотри `scripts/lib/brand.mjs` для точного контракта. Запусти `npm run design -- validate`. Проверяются основные пары текста, не все возможные наложения. При брендовой палитре с низким контрастом подбери доступный UI-вариант с объяснением.

`public/` — явная граница публикации. Генератор копирует только разрешённые изображения/шрифты в `/brand-assets/`. Не клади туда исходные документы, контакты, JSON и отчёты. SVG сначала переведи в разрешённый растр подходящим локальным инструментом; не правь оригинал. Для общего логотипа добавь необязательное поле `logo: "logo.png"` в brand.json и соответствующий файл в public/: он появится на сайте и в панели. Подбери безопасную подложку в обеих темах. Для локального лицензированного шрифта: `fontFace: { "family": "Company Sans", "file": "company.woff2" }` и `font: "Company Sans, Arial, sans-serif"`. Генератор добавит @font-face для сайта и панели. Проверь загрузку и кириллицу; не скачивай шрифты автоматически.

## Применение

`npm run update:website` берёт приватный `site/index.html`, если он есть и включён бренд; иначе шаблон blueprint. Сохрани data-frontsmith-* для обновляемых сведений/услуг, имена формы и её обработчики, script.js, ChatCops и chat-widget.js. Не встраивай цены/контакты копиями вне этих привязок. Перед заменой проверь исходный шаблон профиля. Состав секций и композиция свободны: не ограничивайся перекраской старого шаблона.

Генерация добавляет общий theme controller, семантические токены и CSS-мост; site.css идёт последним. Файлы в design/site — источник, website — результат. Не обходи защиту ручных правок через --force: сначала сравни изменения, перенеси согласованные правки в источник и покажи разницу. Принудительная замена требует отдельного явного решения; прежние файлы копируются в каталог данных.

Удалённые из public/ ресурсы убираются из результата только при наличии в предыдущей квитанции генерации. Неизвестные файлы сохраняются; изменённый вручную управляемый ресурс блокирует обновление. При явном --force его версия сначала сохраняется вне репозитория. Изменение, добавление, переименование или удаление public-актива делает этап brand и последующие этапы устаревшими; исследование исходных материалов остаётся актуальным. Старые контрольные точки без отпечатка public/ требуют однократной перепроверки бренда.

Имена ресурсов должны быть уникальными без учёта регистра для совместимости с Windows. Переименование одного файла только по регистру сохраняет результат и обновляет написание имени; фактическое совпадение путей определяется файловой системой. Коллизии в источниках или прошлой квитанции останавливают генерацию до изменений, включая --force: неоднозначность надо устранить по исходным файлам, а не выбирать произвольную версию.

Контактные input должны сохранять имена name="email" и name="phone", соответствующие data-contact-email/phone и принадлежность форме data-intake-form. Проверяется уже преобразованный HTML: переименование через data-frontsmith-attrs тоже отклоняется. Не создавай дублирующие или отключённые контактные поля.

Для email используются type="email" или type="text", для телефона — type="tel" или type="text"; отсутствие type означает text. Checkbox, radio, hidden и остальные неподходящие типы не принимаются. Учитывается отключение через родительский fieldset, включая исключение первого legend по правилам браузера. `npm run test:design:formdata` отдельно проверяет реальный FormData в установленном Edge/Chrome на искусственных HTML-примерах, без установки пакетов и внешней отправки.

Офис получает только фиксированные маршруты брендовых токенов и разрешённых public-ресурсов. Не открывай произвольное чтение design/. Бизнес-логика app.js остаётся общей. Тёмная тема и CSS-мост должны быть пригодны для всех экранов, а не только для снимка обзора. При нехватке общего контракта расширь общий механизм в рамках отдельной задачи, не создавай частную копию office/app.js.

Виджет ChatCops из vendor неизменен. Frontsmith-мост применяет --cc-* CSS-переменные на существующий host; при переключении темы не пересоздавай виджет и не теряй историю, SSE, форму записи или передачу сотруднику. Его дополнительные элементы тоже должны получать фирменные переменные. Новые брендовые виджеты также используют контракт [Generative UI](widget.md).

### Конфигурация виджета

Необязательное для старых установок поле `brand.json.widget` включает новый сценарий; навык заполняет его при новой адаптации. Код проверяет имена public-ресурсов, ограничения текста, уникальность id и типы компонентов. Пример структуры (тексты замени сведениями конкретной компании):

```json
{
  "widget": {
    "question": "С какой задачей помочь?",
    "surface": "plain",
    "geometry": "soft",
    "tones": {"brand":"#8A4B00","darker":"#713D00","lighter":"#A46319","warmer":"#94430A","cooler":"#7C4B20"},
    "start": "start",
    "components": [
      {"id":"start","type":"choices","title":"С какой задачей помочь?","options":[
        {"label":"Подобрать услугу","message":"Помогите подобрать подходящую услугу"},
        {"label":"Уточнить условия","message":"Хочу уточнить условия до обращения"}
      ]},
      {"id":"services","type":"services","title":"Какая услуга вам нужна?"}
    ]
  }
}
```

`object` переопределяет logo только для объекта виджета; `surfaceImage` — декоративное изображение шапки. Оба — плоские имена разрешённых PNG/JPG/WebP из public/. `objectBackground` — необязательная постоянная подложка #RRGGBB для читаемости объекта в обеих темах; по умолчанию light.surface. Для светлого прозрачного логотипа подбери тёмную подложку. Поверхности: plain, woven, layered. `question` и `title` до 160 символов, label до 70, message до 300; 1–8 компонентов, до 6 вариантов в choices. При отсутствии object используется logo; отсутствие логотипа не разрешает выдумывать фирменный знак.

`geometry`: soft, folded, layered; по умолчанию soft. Все включают пять оболочек: object, question, conversation, form, result. Компоненту можно задать `shell: "question"` (по умолчанию) либо `"conversation"`; произвольный HTML, CSS и выбор формы от модели не принимаются. При новом сообщении показывается переписка; после успешного ответа разрешённый компонент может снова открыть компактный вопрос. Заполненная форма и черновик имеют приоритет перед подсказкой.

`tones` содержит пять авторских значений #RRGGBB: brand, darker, lighter, warmer, cooler. brand — точный исходный цвет, darker/lighter — темнее/светлее по яркости; все цвета различаются. Близость и температуру проверяй визуально по материалам. Исходный оттенок используется в декоративном шве оболочки и объекта, логотип не перекрашивается. Генератор заранее готовит доступные пары accent/onAccent для обеих тем: если исходный цвет не отделяется от поверхности с контрастом 3:1, для управления сохраняется доступный акцент темы. Текст на акценте имеет контраст не ниже 4.5:1. Статусы и focus не чередуются. Старый widget без tones получает небольшую детерминированную семью из light.accent при генерации; при новой адаптации задай пять цветов явно и объясни их в BRAND-DESIGN.md.

Каждая оболочка впервые открывается в brand; следующие входы выбирают один из сохранённых оттенков без немедленного повтора. Обычные сообщения в той же оболочке и смена темы не выбирают новый оттенок. Счётчики живут в странице: перезагрузка начинает с brand. Геометрия и палитры загружены до первого открытия, дополнительных запросов к модели нет. При reduced motion переходы и дыхание объекта отключены. Контроллер меняет атрибуты и токены существующих DOM-узлов, сохраняя историю, поток, форму и фокус.

Генератор встраивает только проверенную публичную конфигурацию в JSON-блок frontsmith-widget-config с экранированием HTML. Не добавляй туда внутренние документы и контакты. Модель выбирает id через show_widget_component; защищённый /api/chat/ui возвращает текущий элемент только своему посетителю и перепроверяет каталог. Новый UI не требует подключения CopilotKit или другого облачного сервиса. Старые сайты без widget продолжают прежний сценарий; переход существующей компании выполняется через её приватные источники и update:website.

Корневые website/ и demo/ остаются учебными/публичными исходниками; материалы одной компании туда не переносятся. build:demo не должен содержать частный бренд. Публикация не входит в навык.
