# Проверка результата

1. Структура навыка и все ссылки доступны из чистого клона; Codex действительно обнаруживает frontsmith-brand. Проверка YAML не заменяет запуск навыка.
2. Приёмка дизайна глазами: осмысленная композиция под компанию, достоверный контент, оригинальный сайт и виджет; спокойный рабочий офис. Реальные снимки телефона, планшета и широкого экрана в light/dark; клавиатура, фокус, увеличение текста и reduced motion. Не называй мокап действующим интерфейсом.
3. Функции: навигация, контактная форма без реальной отправки, фильтры, клиентская карточка, расписание и диалоги; открытие/закрытие виджета, сохранение истории при смене темы, форма записи, ошибки и передача сотруднику на искусственных данных. Живые вызовы Codex не обязательны: используй существующие тестовые двойники и сообщи это.
4. `npm run design -- validate`, `npm run check`, `npm test`. При изменении HTML-форм — также `npm run test:design:formdata` с установленным Edge/Chrome: он проверяет настоящую сериализацию формы. При изменении соответствующих сервисов — профильные команды из AGENTS.md. `test:first-run` отдельно проверяет установку; bootstrap/vendor/gitignore требуют release:check. Не запускай платный smoke только ради цвета.
5. Обновление: изменить услугу/текст профиля на искусственной установке, повторить update:website; композиция, бренд, виджет и выбранная тема сохраняются. Ручные правки HTML, CSS и JS не затираются; отказ происходит до изменения сайта. --force отдельно проверить с копиями вне репозитория.
6. Продолжение: в новом сеансе/процессе прочитать status после research и после brand; загрузить только нужный этап, продолжить по артефактам. Изменить исходный материал, затем результат этапа — зависимые состояния должны стать stale. Прерванный незавершённый этап не объявляется complete.
7. Независимый пример: второй набор искусственных материалов другой сервисной компании, другой визуальный характер и состав контента. Новому исполнителю передать только навык, сырьё и обычный запрос владельца; не передавать ожидаемый ответ или прошлые решения. Рабочая область и каталог данных отдельные. Оценить фактические интерфейсы и действия. Автотест генератора доказывает механику, но не оригинальность дизайна.

В review/verification.md укажи конкретные выполненные команды и исходы, пути снимков, проверенные сценарии, непроверенное и следующий шаг. Если браузера/визуального инструмента нет, техническую готовность и визуальную приёмку раздели; не ставь финальную контрольную точку как будто всё проверено.
