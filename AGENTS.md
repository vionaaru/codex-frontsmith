# Инструкции Codex для Frontsmith

## Чтение файлов в Windows

- При чтении текстовых файлов через PowerShell используйте `Get-Content -Encoding UTF8 -LiteralPath ...`.
- Если кириллица отображается как `Р...` или `вЂ...`, сначала считайте это проблемой декодирования терминала, а не повреждением файла.

## Границы продукта

Frontsmith — самостоятельный продукт с открытым исходным кодом: универсальный стартер-кит цифрового офиса небольшой сервисной компании для работы через Codex.

Frontsmith — не программа для автосервиса. Автосервис — один из отраслевых профилей.

## Направление v1.0

Основной интерфейс оператора — Codex вместе с файлами репозитория, рабочими процессами и скриптами. Локальная панель офиса (`npm run frontsmith`, `http://127.0.0.1:4180`) показывает клиентов, обращения, задачи, услуги и расписание. Онлайн-Панель демонстрации в `demo/` показывает работу через Codex; `codex-frontsmith.example` — заглушка будущего домена, а не работающий сайт.

Возможности v1.0 по умолчанию:

- Настройка компании
- Сводка владельца
- Сайт
- Работа с клиентами
- Сметы и коммерческие предложения
- План запуска
- Журнал действий
- Настройки и подключения
- Планирование расширений

Отзывы, маркетинг, публикации в соцсетях, платежи, счета, бухгалтерия, внешние CRM, мессенджеры и телефония не входят в v1.0. Это будущие расширения.

Сводка владельца (Owner Brief) — продуктовое название модуля текущего состояния. Используйте его вместо `Business Pulse`, `Front Office Pulse` или общих формулировок о «пульсе бизнеса». Обещание продукта — «вести цифровой офис», а не «управлять бизнесом».

## Архитектура

```text
офис и Codex-инструменты
  -> CustomerProvider (client_id)          office/customers/
       -> crmkit, встроенный CRM            services/crm/
  -> Privacy Service: pii-guard + NER       services/privacy/
       -> Codex App Server, вход ChatGPT    services/codex-host/
```

- Клиенты существуют только через CustomerProvider. В офисной базе — `client_id`, контакты хранит crmkit. Не читайте и не пишите имена, телефоны и email клиентов в обход CustomerProvider и не создавайте альтернативный провайдер.
- Всё, что уходит в модель, проходит через Privacy Service. Отказ Privacy Service блокирует обращение к модели (fail closed).
- AI-контур — Codex App Server по подписке ChatGPT в отдельном `CODEX_HOME`. OpenAI API key не используется.
- Отраслевое поведение задаёт бизнес-профиль в `blueprints/`: `generic-service` по умолчанию, `auto-service` — по явному выбору. Профиль включает отраслевые разделы (`officeModules`) и подписи статусов и категорий (`vocabulary`). Машинные идентификаторы статусов общие для всех профилей; меняйте только подписи.
- Ядро — CustomerProvider, crmkit, Privacy Service, Codex Host — от профиля не зависит.

## Где что хранится

| Место | Что | В Git |
| --- | --- | --- |
| репозиторий | код, миграции, шаблоны, профили, тесты, документация | да |
| `vendor/` | зафиксированные crmkit, pii-guard, модель NER, uv, Python, wheels; `vendor/manifest.json` | да, большие файлы через Git LFS |
| `.frontsmith/business/` | профиль компании, офисная база без контактов клиентов, черновики, отчёты, рабочий сайт | нет |
| каталог данных (`%LOCALAPPDATA%\Frontsmith` или выбранный при первом bootstrap, указатель — `%LOCALAPPDATA%\Frontsmith\data-root.txt`) | контакты crmkit и его учётные данные, состояние Privacy Service, runtime, вход Codex Host, резервные копии | нет |

- Каталог данных всегда вне репозитория: репозиторий — рабочая область Codex. Не копируйте оттуда файлы в репозиторий и не читайте содержимое CRM, privacy-состояния и входа Codex без прямой задачи.
- Резервные копии офисной базы — в `<каталог данных>\backups\`. Не сохраняйте копии баз внутри репозитория.
- Корневой `website/` — отслеживаемый код и учебный шаблон; генерация его не меняет. `build:demo` не включает приватные данные. Не добавляйте данные в Git через `git add -f`.
- Не удаляйте и не переносите пользовательские данные, копии и существующий каталог данных без прямого поручения владельца.

## Поставка и Bootstrap

- `npm run bootstrap` ставит всё из `vendor/` и ничего не скачивает. Не добавляйте в Bootstrap загрузки из интернета, `git clone`, `uv python install` или переход на другую версию компонента.
- Файлы в `vendor/` — неизменённый сторонний код. Не правьте их. Дополнения Frontsmith к pii-guard — в `services/privacy/frontsmith_privacy/`.
- Обновление компонента — отдельное решение владельца по порядку из `vendor/README.md`, с пересборкой `vendor/manifest.json` (`npm run vendor:manifest`) и атрибуцией в `THIRD_PARTY_NOTICES.md`.
- Поддерживаемая установка — Windows x64. Не заявляйте поддержку Linux и macOS, пока для них нет артефактов в поставке.
- Bootstrap идемпотентен: повторный запуск не меняет каталог данных, CRM, вход Codex, профиль и записи.

## Проверки

- `npm run check` и `npm test` — после любых изменений кода.
- `npm run test:privacy`, `npm run test:crm`, `npm run test:codex-host:app-server` — при изменениях Privacy Service, CRM и Codex Host.
- `npm run release:check` — перед публикацией и после изменений `vendor/`, `.gitattributes`, `.gitignore` и Bootstrap.
- `npm run smoke:codex-host` тратит лимиты подписки: запускайте только по необходимости.

## Правила выполнения

- Сохраняйте самостоятельную ценность Frontsmith прежде, чем добавлять публичные формулировки о Neura.
- Ограничьте Сводку владельца состоянием, препятствиями, согласованиями и следующими действиями одной компании.
- По умолчанию перед реальным действием используйте черновик, предпросмотр, согласование владельца и пробный прогон.
- Рабочие учётные данные, сообщения клиентам, публичные публикации, отправка данных сервисам, изменения DNS, публикация репозитория и внешние действия требуют явного согласования владельца.
- Пишите прямо, решительно и с высокими требованиями к качеству.
- Не добавляйте документы планирования, если существующие управляющие документы уже фиксируют решение.

## Стандарт качества

Каждый результат под именем Frontsmith должен быть:

- понятным владельцу малого бизнеса;
- убедительным для разработчиков;
- полезным до регистрации в Neura;
- подконтрольным Neura при включённом режиме подключённого клиента;
- достаточно узким по объёму, чтобы оператор мог выполнить работу без разрастания задач.

## Правила публичного оформления

Публичные заголовки, подзаголовки, видеоподписи и вводные тексты разделов должны аккуратно помещаться в свои блоки.

- Избегайте неудачных переносов на две строки, одиноких слов и обрезанного текста.
- Не ставьте точки в конце названий, заголовков, подзаголовков и строк видеоподписей.
- При неудачных переносах сначала сократите текст, затем настройте адаптивный размер или компоновку.
- При повторении существующего оформления другой страницы Neura/Frontsmith воспроизводите типографику, отступы, оформление иконок и адаптивное поведение, а не придумывайте похожий стиль.
