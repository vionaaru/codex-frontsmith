# Фактура — учебная фирменная адаптация

Пример для презентации Frontsmith: из описания компании, логотипа и четырёх изображений Codex разрабатывает лендинг, оформление офисной панели и Generative UI виджета. «Фактура» — вымышленный сервис ухода за мягкой мебелью. Все изображения синтетические; реальных клиентов, отзывов и выполненных заказов в наборе нет.

Исходный каталог для навыка: **[brand-materials/](brand-materials/README.md)**. Внутри находятся бриф README.md, logo/, images/ и справка provenance/. Композиция, палитры, интерфейсы и контрольные точки создаются при прохождении навыка. Рабочая база, контакты, вход ChatGPT и состояние прежнего предпросмотра в пример не входят.

## 1. Подготовить отдельный клон

Требования к Windows x64, Node.js, Git LFS и месту на диске описаны в [установке Frontsmith](../../README.md#установка). Пример входит в основную ветку main. В новом каталоге выполните:

```powershell
git clone https://github.com/vionaaru/codex-frontsmith.git frontsmith-faktura-demo
Set-Location frontsmith-faktura-demo
git lfs pull
npm install
```

Откройте этот клон в Codex. Убедитесь, что он видит [frontsmith-brand](../../.agents/skills/frontsmith-brand/SKILL.md). Материалы уже находятся в examples/faktura/brand-materials/; дополнительно скачивать или генерировать картинки не нужно.

## 2. Подготовить изолированную учебную установку

В PowerShell из корня нового клона задайте пути только для текущего процесса. Внешний каталог ниже создаётся рядом с клоном. Проверка существования защищает уже подготовленный пример от повторной первоначальной настройки:

```powershell
$env:FRONTSMITH_BUSINESS_ROOT = Join-Path (Get-Location).Path '.frontsmith\training\faktura'
$env:FRONTSMITH_DATA_ROOT = Join-Path (Split-Path (Get-Location).Path -Parent) 'frontsmith-faktura-demo-data'
if ((Test-Path -LiteralPath $env:FRONTSMITH_BUSINESS_ROOT) -or (Test-Path -LiteralPath $env:FRONTSMITH_DATA_ROOT)) {
    throw 'Учебный каталог уже существует. Продолжите его настройку или выберите новую пару каталогов'
}
npm run bootstrap -- --blueprint generic-service
```

Bootstrap использует поставку vendor/ и готовит отдельный generic-service. FRONTSMITH_DATA_ROOT не меняет сохранённый указатель каталога данных другой установки. Не используйте --reset и не копируйте базу, контакты или вход ChatGPT из действующего офиса. Для первого визуального среза вход в AI не обязателен.

Передайте Codex оба получившихся абсолютных пути: переменные терминала не обязательно доступны его отдельным процессам. Попросите применять их ко всем командам этого примера. При продолжении используйте те же пути и начинайте с design status, без повторного блока первоначальной настройки.

## 3. Запустить навык

Вставьте запрос в Codex, добавив пути из шага 2:

```text
Используй $frontsmith-brand для учебной компании «Фактура».
Материалы: examples/faktura/brand-materials/ от корня проекта.
Рабочая область бизнеса: .frontsmith/training/faktura/ в этом клоне.
Каталог данных: ../frontsmith-faktura-demo-data/ относительно корня клона.
Если при подготовке выбраны другие пути, используй переданные мной абсолютные пути.
Применяй FRONTSMITH_BUSINESS_ROOT и FRONTSMITH_DATA_ROOT ко всем командам.

Проверь подготовленный профиль generic-service и начни с design status.
Прочитай README.md, визуально изучи логотип и четыре изображения.
Скопируй исходники в приватный design/inputs/ этой рабочей области;
для сайта отбирай разрешённые изображения в design/public/.
Разработай оформление лендинга, офисной панели и виджета,
проходя этапы навыка и сохраняя результаты и контрольные точки.

Сначала покажи работающий предпросмотр: первый экран и две секции
лендинга, пять представлений виджета с подготовленными фирменными
оттенками, таблицу и форму офиса. Проверь светлую и тёмную темы,
мобильный и широкий экраны. Для виджета используй логотип как
начальный объект, релевантную ткани поверхность, полезные варианты
выбора и свободный ввод. Видеоприветствие и аватар не нужны.

Новые размеры, контуры, компоненты и оттенки должны выбираться
из готовых элементов. Генерация HTML/CSS моделью во время разговора
не нужна. При отключённом AI честно покажи недоступность;
динамику и форму можно проверить на явно обозначенных учебных
двойниках без настоящих заявок и расходования лимитов подписки.

Все сведения и изображения учебные. Не выдумывай цены, часы,
географию, отзывы и выполненные заказы. Для таблицы и формы
используй явно учебные записи только через CustomerProvider.
Текущий офис, его данные, исходный набор examples/ и общий
учебный website/ не изменяй. Если обычные порты заняты,
используй свободные и сообщи адреса.
Покажи результат для согласования перед полной адаптацией.
Публикация и внешняя отправка не требуются.
```

## 4. Провести презентацию

Покажите исходный каталог, затем откройте реальные адреса созданного предпросмотра. Сравните первый экран и две секции лендинга, таблицу и форму офиса в двух темах и на двух ширинах. В виджете покажите фирменный объект, компактный вопрос, переписку, развёрнутую форму и компактный результат; проверьте свободный ввод, сохранение полей и чередование подготовленных оттенков при повторном входе.

Обозначьте использование учебных ответов, если AI не подключён. Выбор услуги и отправка тестовой формы не являются реальной записью. Живой диспетчер требует отдельной настройки знаний, расписания и входа в изолированном каталоге данных; её порядок описывает [frontsmith-dispatcher](../../.agents/skills/frontsmith-dispatcher/SKILL.md).

Сохранённые research.md, BRAND-DESIGN.md, brand.json, отчёты review/ и контрольные точки находятся в design/ учебной рабочей области. Команда `npm run design -- status` с её переменными показывает, откуда продолжать. После согласования можно перейти к полной адаптации.

Для компании клиента тот же процесс начинается с её каталога исходных материалов. Публичный учебный набор остаётся в examples/, а материалы и результаты клиента хранятся в его приватной рабочей области.
